# 数据质量管理

本项目会自动过滤低质量对局，确保分析结果的准确性。

## 什么是低质量对局？

低质量对局是指：
- **玩家在非最后一局掉线且未重连**

这些对局会被自动过滤，因为掉线期间系统会自动摸切，不代表玩家的真实决策。

**例外**：如果玩家在最后一局掉线（提前离开），对局仍会保留，因为这是正常行为。

## 自动过滤机制

### 1. 现有数据已清理

当前数据库中的所有对局都已经过质量检查，低质量对局已被移除。

统计数据：

### 2. 新数据自动清理

当您下载新的对局数据后，运行以下命令自动清理：

```bash
py clean_new_logs.py
```

这个脚本会：
1. 检查所有新导入的对局
2. 自动删除低质量对局
3. 压缩数据库以节省空间

### 3. 手动清理（可选）

如果需要重新检查整个数据库，可以运行：

```bash
# 试运行（不删除，只统计）
py clean_bye_logs.py

# 实际执行删除
py clean_bye_logs.py --execute
```

## 如何判断玩家是否重连？

系统通过检查 mjlog XML 中的标签来判断：

1. **`<BYE who="N"/>`** - 玩家 N 掉线
2. **`<UN nN="..."/>`** - 玩家 N 重连

如果在同一小局中，`<BYE>` 后出现对应玩家的 `<UN>` 标签，说明玩家已重连，对局保留。

from src.log_quality import check_log_quality_compressed

is_valid, reason = check_log_quality_compressed(compressed_log_data)

if not is_valid:

### 核心模块

- **`src/log_quality.py`**: 对局质量检查模块
- **`clean_bye_logs.py`**: 清理整个数据库
- **`clean_new_logs.py`**: 只清理新导入的对局

## 常见问题

### Q: 为什么要删除掉线对局？

A: 掉线期间系统会自动摸切，不代表玩家的真实打牌策略，会污染分析结果。

### Q: 如何知道有多少对局被删除了？

A: 运行清理脚本时会显示详细统计：

```
处理完成！
  保留: 290,874 条 (98.93%)
  删除: 5,671 条 (1.93%)

删除原因统计:
  玩家0在非最后一局掉线且未重连: 1,478 条
  玩家1在非最后一局掉线且未重连: 1,457 条
  玩家2在非最后一局掉线且未重连: 1,405 条
  玩家3在非最后一局掉线且未重连: 1,331 条
```

### Q: 删除后能恢复吗？

A: 删除后无法恢复。建议在首次运行时先使用试运行模式（不加 `--execute`）查看统计结果。

### Q: 多久需要清理一次？

A: 每次下载新数据后运行一次 `clean_new_logs.py` 即可。
